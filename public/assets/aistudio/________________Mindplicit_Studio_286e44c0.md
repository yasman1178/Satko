# خطة بناء برنامج Mindplicit Studio لإنتاج الفيديوهات (Next.js)

*خطة عمل تنفيذية | أكتوبر 2026*

## 1. الهدف والقرارات المعتمدة

برنامج ويب (Next.js) يحوّل ملف JSON خارج من NotebookLM إلى فيديو طويل كامل جاهز للنشر، بنفس ترتيب الملف.

| البند | القرار |
| --- | --- |
| نوع الفيديو | طويل 16:9، حوالي 25 إلى 30 دقيقة |
| المجال | سيكولوجيا سوداء وماكيافيلية بزاوية توعوية: إزاي تحمي نفسك من التلاعب |
| لغة التعليق | إنجليزي عبر Edge-TTS |
| الصور | تتولد بره (ImageFX أو Whisk) وتترفع بأسماء مطابقة للـ JSON |
| التركيب | في المتصفح |
| التأثيرات | ترجمة مكتوبة، Zoom/Pan، انتقالات Fade/Dissolve، موسيقى بخفض تلقائي وقت الكلام |
| إضافات | عناوين ووصف وتاجات للنشر، وحفظ المشاريع واستكمالها لاحقاً |

## 2. خط العمل (Pipeline)

1. **NotebookLM:** مصادرك (كتب أو ملفات) تتحول لـ JSON بالهيكل المتفق عليه.
2. **استيراد وفحص:** البرنامج يفحص الـ JSON ويعرض الأخطاء بالمشهد والسطر.
3. **الصوت:** توليد صوت كل مشهد بـ Edge-TTS وقياس مدته الفعلية.
4. **الصور:** رفع جماعي ومطابقة بالأسماء، مع تقرير بالناقص والزايد.
5. **Timeline:** مدة كل مشهد = مدة صوته + 0.2 ثانية، والترجمة من توقيت الكلمات.
6. **معاينة** كاملة قبل التصدير.
7. **Render** على أجزاء ثم دمجها في ملف mp4.
8. **حزمة النشر:** عناوين، وصف، تاجات، برومبت الغلاف، تعليق مثبت.

**قاعدة ثابتة:** مدة المشهد تتحدد من طول ملف صوته الحقيقي، والصورة ما تتبدلش قبل ما صوت مشهدها يخلص أبداً.

## 3. عقد الـ JSON (اللي NotebookLM يطلّعه)

| المستوى | الحقول |
| --- | --- |
| project | title، language (en)، voice، target\_minutes |
| chapters\[\] | chapter\_id، title |
| scenes\[\] (جوه كل فصل) | scene\_id متسلسل، narration\_text، image\_filename، image\_prompt\_en، motion، transition |
| publish | title\_options (٣)، description، tags\[\]، thumbnail\_prompt\_en، pinned\_comment |

**القيم المسموحة:** motion = zoom\_in أو zoom\_out أو pan\_left أو pan\_right أو static. transition = fade أو dissolve أو cut.

**قواعد:**

- `image_filename` فريد وبصيغة ثابتة مثل scene\_001.png.
- الجملة الواحدة للمشهد من 15 إلى 30 كلمة، والفيديو كله حوالي 4000 إلى 4200 كلمة (حوالي 200 مشهد).
- ممنوع علامات الاقتباس المزدوجة جوه النص، وJSON صالح 100%.
- برومبت NotebookLM اللي يطلّع الشكل ده بنكتبه في المرحلة 0.

## 4. التقنيات المقترحة

| الطبقة | الاختيار | ملاحظة |
| --- | --- | --- |
| الواجهة | Next.js (App Router) + TypeScript + Tailwind |  |
| فحص الـ JSON | Zod | رسائل أخطاء مفهومة |
| حفظ المشاريع | IndexedDB (مثل Dexie) | الصوت والصور ملفات كبيرة، فتتحفظ في المتصفح، مع زر تصدير واستيراد المشروع كملف |
| الصوت | Route في Next.js تستدعي Edge-TTS عبر مكتبة Node | الخدمة غير رسمية، فلازم Cache وإعادة محاولة |
| المعاينة | Canvas + Web Audio |  |
| خلط الصوت والموسيقى | OfflineAudioContext | خفض الموسيقى تلقائياً وقت الكلام |
| التركيب | Canvas + WebCodecs + muxer لـ mp4 (المحرك الأساسي)، وffmpeg.wasm احتياطي | انظر التنبيه تحت |
| الاستضافة | Vercel للواجهة والـ API الخفيف | الـ render كله عند المستخدم |

**تنبيه مهم عن ffmpeg.wasm:** اخترت التركيب في المتصفح، وده ممكن. لكن فيديو نص ساعة بـ 1080p على ffmpeg.wasm وحده بطيء ويستهلك ذاكرة كبيرة وممكن يوقف. لذلك أقترح محرك أساسي بـ Canvas وWebCodecs (أسرع وأخف، ويتحكم في Zoom/Pan والترجمة بالكود)، وffmpeg.wasm يفضل احتياطي للمتصفحات اللي مش بتدعم WebCodecs. الدعم الكامل متوقع على Chrome وEdge للكمبيوتر، فنتحقق منه في المرحلة 5.

## 5. مراحل التنفيذ

| المرحلة | المطلوب | معيار القبول |
| --- | --- | --- |
| 0. العقد | برومبت NotebookLM + JSON Schema + عينة JSON | NotebookLM يطلّع JSON يعدي الفحص من أول مرة تقريباً |
| 1. الأساس | مشروع Next.js، استيراد JSON، فحص، حفظ المشاريع | إعادة فتح المشروع بعد قفل المتصفح |
| 2. الصوت | Edge-TTS لكل مشهد، Cache، قياس المدة، إعادة توليد مشهد واحد | 200 مشهد يتولدوا، والمشهد الفاشل يتعاد لوحده |
| 3. الصور | رفع جماعي، مطابقة بالاسم، تقرير الناقص | البرنامج يرفض الـ render لو في صورة ناقصة |
| 4. Timeline والمعاينة | قايمة مشاهد، معاينة، ضبط الحركة والانتقال، ترجمة | مفيش مشهد بيتغير قبل ما صوته يخلص |
| 5. الـ Render | محرك التركيب، أجزاء، موسيقى بخفض تلقائي، تصدير mp4، شريط تقدم، استكمال بعد الفشل | فيديو 25 إلى 30 دقيقة يتصدر على جهازك بدون crash |
| 6. النشر | عناوين، وصف، تاجات، غلاف، تعليق مثبت، أزرار نسخ | حزمة النشر تتحفظ مع المشروع |
| 7. الصقل | معالجة الأخطاء، الأداء، تجربة 3 فيديوهات حقيقية، نشر على Vercel | 3 فيديوهات تخلص من الاستيراد للتصدير بدون تدخل يدوي |

## 7. المخاطر وحلولها

| الخطر | الحل |
| --- | --- |
| Edge-TTS غير رسمي وممكن يتأخر أو يتحجب | Cache لكل مشهد، إعادة محاولة، طابور بسرعة محسوبة، وطبقة مزود صوت بديل (مثل Azure TTS الرسمي) من البداية |
| ذاكرة المتصفح في 30 دقيقة | Render على أجزاء، حد أقصى 1080p و30 إطار، وخيار 720p، وتفريغ الذاكرة بين الأجزاء |
| WebCodecs مش في كل المتصفحات | Chrome وEdge كمتصفحات مدعومة، وffmpeg.wasm احتياطي |
| JSON غير ثابت من NotebookLM | Schema صارم، رسائل أخطاء واضحة، وزر إصلاح بسيط |
| أخطاء تسمية الصور | صيغة scene\_001، وفحص قبل الـ render |
| حقوق الموسيقى | موسيقى مرخصة أو Royalty-free فقط |
| سياسة يوتيوب على المحتوى المكرر المنتج بكميات | مراجعة بشرية لكل سكريبت، تنوع في الأسلوب، وقيمة حقيقية للمشاهد |
| انحراف المحتوى عن الزاوية التوعوية | بند مراجعة: السكريبت يشرح الحماية من التلاعب، مش طرق التلاعب |

## 8. قرارات مفتوحة

- العناوين والوصف: من الـ JSON اللي بيطلّعه NotebookLM (بدون API)، ولا عن طريق مفتاح LLM جوه البرنامج؟
- مصدر الموسيقى: ملفات ترفعها أنت، ولا مكتبة جاهزة؟
- جودة التصدير الافتراضية: 1080p ولا 720p؟
- المستخدم: أنت لوحدك، ولا هيتاح لغيرك لاحقاً (بيغير التخزين والتسجيل)؟

## 9. الخطوة الجاية

أكتب لك برومبت NotebookLM اللي بيطلّع الـ JSON (المرحلة 0)، وبعده برومبت بناء المرحلة 1 لـ Google AI Studio.
